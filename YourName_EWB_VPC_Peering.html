5 Viva Defense & Architecture Analysis 10 Marks

1. Why is the return route needed?
Routing is hop-by-hop and directional. When App-A transmits an ICMP Echo Request, VPC A directs the packet to the peering connection. However, when App-B generates the ICMP Echo Reply destined for 10.10.2.10, VPC B's virtual router consults its own route table (ewb-rt-b-private). Without an explicit entry directing 10.10.0.0/16 to the peering connection, VPC B cannot resolve the next hop and discards the reply. Both directions require explicit routes.
2. Why is the App-B SSH source the bastion private IP?
When using OpenSSH ProxyJump, the client workstation establishes a transport tunnel to the Bastion. The Bastion SSH daemon then spawns a brand new, outbound TCP connection to App-B (10.20.1.10:22). Because the TCP SYN packet is initiated directly from the Bastion's network interface, the IP source address header is the Bastion's private IP (10.10.1.10). Consequently, App-B's firewall only needs to permit inbound traffic from 10.10.1.10/32.
3. Why does Active peering not guarantee a successful ping?
An Active peering connection only represents an established logical interconnect in the AWS SDN control plane. For user packets to traverse and be accepted: (1) Route tables in both VPCs must have explicit route entries for the peer CIDR, (2) The target host's Security Group must explicitly permit inbound ICMP Echo Request (Type 8, Code 0), and (3) Subnet NACLs must allow the traffic. By default, AWS Security Groups drop all unsolicited inbound traffic.
4. Can VPC B use VPC A's internet gateway over peering?
No. AWS VPC Peering is strictly non-transitive and does not support edge-to-edge routing. Traffic entering a VPC over a peering connection cannot exit via an Internet Gateway, NAT Gateway, or Virtual Private Gateway. For transitive connectivity or centralized internet egress, AWS Transit Gateway (TGW) must be utilized.

Key Engineering Takeaways
1. Defense in Depth: Layering non-overlapping CIDRs, isolated route tables, and strict /32 security groups delivers comprehensive workload isolation.
2. Credential Hardening: ProxyJump guarantees that master SSH credentials never touch intermediate bastion hosts, thwarting credential theft.
3. Symmetrical Routing Awareness: Verifying bidirectional route table symmetry is paramount for all distributed cloud interconnects.
